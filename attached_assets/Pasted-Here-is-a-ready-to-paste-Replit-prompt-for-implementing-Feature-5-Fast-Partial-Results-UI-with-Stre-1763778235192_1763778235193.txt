✅ Replit Prompt: Implement Fast Partial Results UI (Streaming Interim Results)

Prompt:

Implement a “Fast Partial Results” UI for the ingredient analysis screen in my Auraly app.
The goal is to show the user results as they become ready rather than waiting for all ingredients to finish processing.

Requirements

1. Backend: Streaming API Endpoint

Create a new endpoint:

POST /stream-ingredient-analysis

This endpoint should:
	•	Accept:

{
  "ingredients": ["ingredient A", "ingredient B", ...],
  "category": "food" | "skincare" | "haircare" | etc.
}


	•	Use Server-Sent Events (SSE) or websocket streaming (SSE is preferred and simpler).
	•	For each ingredient:
	1.	Check the cache first.
	2.	If a valid cached analysis exists → immediately stream an SSE event:

event: ingredientResult
data: { ingredient: "...", analysis: "...", fromCache: true }


	3.	If the cache is missing or expired:
	•	Kick off the AI analysis.
	•	Once the AI result is ready, stream:

event: ingredientResult
data: { ingredient: "...", analysis: "...", fromCache: false }


	4.	Continue streaming results as soon as each ingredient finishes — do NOT wait for all to complete.

	•	When all ingredients have streamed, send a final event:

event: done
data: "complete"


	•	Ensure the endpoint:
	•	Uses Content-Type: text/event-stream
	•	Flushes after every event
	•	Keeps the connection open until everything is sent
	•	Handles network disconnects gracefully

2. Backend Helper Logic

Use helper functions:
	•	fetchCachedAnalysis(ingredient, category)
	•	shouldRefreshCache(entry) (30-day expiration)
	•	analyzeIngredient(ingredient, category)
	•	updateCache(ingredient, category, analysis)

3. Frontend: Streaming UI Behavior

Update the ingredient analysis page to support streaming.

The UI should:
	•	Show a loading state immediately
	•	As soon as an ingredient result arrives, append it to a results list
	•	Render results one-by-one (like a chat stream)
	•	Reorder if necessary so the UI stays alphabetical or in the product’s ingredient order
	•	Highlight cached results with a small tag (“cached”)
	•	Automatically scroll as new results come in
	•	When the final done event arrives:
	•	Hide loading spinner
	•	Show “Analysis Complete”

4. Frontend Streaming Implementation

Use the browser-native EventSource:

const es = new EventSource('/stream-ingredient-analysis');
es.addEventListener('ingredientResult', (event) => {
  const payload = JSON.parse(event.data);
  // Add this result to the UI immediately
});
es.addEventListener('done', () => {
  es.close();
  // Mark UI as finished
});

Show results like:

[Ingredient name]
Risk: ...
Category-specific comments...
(from cache or fresh AI)

5. Error Handling

Backend:
	•	If one ingredient fails, stream:

event: ingredientError
data: { ingredient: "...", error: "message here" }


	•	Continue processing the others.

Frontend:
	•	Show a red inline error for failed ingredients but continue showing other streaming results.

6. Tech Stack
	•	Node.js (Express)
	•	SSE for streaming
	•	SQLite or Replit DB for cached results

7. Code Style
	•	Modern JS (async/await)
	•	Clearly commented and modular
	•	No placeholder logic — generate actual working SSE code
